# Synthesis: performance-literature basis for the fdtdx patches

Scope discipline: everything below is drawn only from the four lane reports. Measured facts used: 648 B/cell/step vs ~80–100 B lean (Minkov et al. count 144 B/cell/step for a no-reuse lean Yee update); component-split layout 1.89x bitwise-identical; jnp.stack/concatenate = 34% of device time; 37 full-volume CPML auxiliary scalars; XLA flags ~0%; CUDA MPS −58%; 890 Mcells/s (RTX 6000 Ada) / 706 Mcells/s (Quadro RTX 6000) at ~100% of achieved streaming bandwidth.

## 1. Adoption-ranked technique list (impact / effort)

See `adoption_candidates` for the ranked list with per-item citations. Ranking logic, from the lanes: kernels are already at ~100% of streaming bandwidth, so the only lever is bytes moved (Kim/Kim/Park roofline; Minkov et al.; Livesey et al.). The two in-flight patches attack the two biggest traffic terms (packing copies, full-volume CPML auxiliaries) and are pure JAX-level restructurings; everything ranked below them is either smaller (LUT ~20%, per Weldon), orthogonal (symmetry, monitors), or requires leaving XLA (temporal blocking). Streaming fp32 GPU FDTD implementations cluster between ~100 B/cell/step (Tidy3D) and ~600 B/cell/step (straightforward CUDA); fdtdx's 648 sits at the heavy end, and the patches move it toward the efficient edge without algorithmic change.

## 2. Prior-art paragraph drafts for the upstream PR

### (a) Boundary-region-only CPML storage

> CPML memory variables are boundary-layer quantities by construction: outside the absorbing layer the CPML coefficients reduce to b = 1, a = 0, so auxiliaries initialized to zero remain exactly zero (Roden & Gedney 2000, https://onlinelibrary.wiley.com/doi/10.1002/1098-2760(20001205)27:5%3C334::AID-MOP14%3E3.0.CO;2-A; Li et al. 2008, https://engineering.purdue.edu/oxidemems/conferences/ultrasonics2008/files/IUS2008-001011.pdf — "The memory variables are set to zero outside the C-PML zones, so (8) need only to be solved in a small part of the calculation domain"; Johnson, Notes on PMLs, https://arxiv.org/pdf/2108.05348). Full-domain versus boundary-only allocation is a documented, named tradeoff — full-domain simplifies the loop structure while boundary-only saves memory, and on memory-bound GPUs the boundary-only variant is the better option (Padilla-Perez et al. 2022, https://doi.org/10.3390/app122211430) — and boundary-only storage is standard practice in production FDTD codes: gprMax allocates slab-shaped per-face auxiliary arrays (Warren et al. 2019, https://doi.org/10.1016/j.cpc.2018.11.007), B-CALM stores its "recursive accumulators only ... in the PML regions" (Wahl et al. 2012, https://ee.stanford.edu/~dabm/407.pdf), flaport/fdtd shapes each face's psi arrays as (thickness, Ny, Nz) (https://raw.githubusercontent.com/flaport/fdtd/master/fdtd/boundaries.py), and fdtd-z restricts PML to the z-axis precisely so its cost does not "spread across a large portion of the simulation domain" (https://github.com/spinsphotonics/fdtdz). A slab-confined CPML measures below 1% of runtime across 320³–800³ grids (Obieke, https://arxiv.org/abs/2606.06910; acoustic FDTD — cite for the confinement overhead, not EM throughput), whereas heavy CPML usage has been documented to cost up to 50% (Weldon et al. 2010, https://journals.riverpublishers.com/index.php/ACES/article/download/15667/12713/47773), and CPML's own history is a boundary-memory-reduction story (>70% storage reduction in the PML regions vs split PML — Martin & Komatitsch 2009, https://academic.oup.com/gji/article/179/1/333/738594). This change extends FDTDX's existing boundary-memory-efficiency line — the time-reversal gradient work already stores only interface slices and compresses them to fp16/fp8 (https://arxiv.org/html/2603.24027) — from gradient recording to the forward pass, moving measured traffic from 648 B/cell/step toward the ~100–146 B/cell/step budget at which bandwidth-limited GPU FDTD operates (Minkov et al., OPN 2024, https://www.optica-opn.org/home/articles/volume_35/september_2024/features/gpu-accelerated_photonic_simulations/).

### (b) Component-split state layout

> Separate per-field-component arrays are the canonical GPU finite-difference layout (Micikevicius, GPGPU-2 2009, https://dl.acm.org/doi/10.1145/1513895.1513905; Livesey et al., https://www.remcom.com/hubfs/Squarespace%20Resources/ImpactOfGPUMemoryAccessPatternsOnFDTD.pdf, where coalesced vs uncoalesced FDTD configurations differ by roughly an order of magnitude and runtime tracks memory bandwidth, not FLOPs), and a recent GPU FDTD solver explicitly splits computation into per-component kernels for cache and shared-memory efficiency (HoseinyFarahabady & Zomaya, ICCS 2024, https://doi.org/10.1007/978-3-031-63751-3_24). Data-layout transformation is an established optimization for memory-bound structured-grid GPU codes generally (Sung, Stratton & Hwu, PACT 2010, https://experts.illinois.edu/en/publications/data-layout-transformation-exploiting-memory-level-parallelism-in/; Tran, Lee & Hong 2017, https://www.hindawi.com/journals/sp/2017/1205892/, where SoA variants decisively beat AoS on a GPU lattice-Boltzmann solver). Under XLA the fused (3, Nx, Ny, Nz) layout additionally forces jnp.stack/concatenate into the hot loop, which XLA excludes from fusion when the concatenate has more than one user; Snider & Liang (https://arxiv.org/abs/2301.13062) measured 3.41x from passing state values individually instead of concatenated — and only ~10% from forcing concatenate fusion in the compiler, because memory movement, not launch overhead, is the bottleneck. This patch applies the same restructuring to FDTD field state and measures a bitwise-identical 1.89x (the stack/concatenate accounted for 34% of device time); we found no physics-in-JAX publication documenting the fused-axis-vs-per-component tradeoff for PDE field state, so we report the measurement as a new data point alongside this prior art.

- Roden & Gedney 2000 and Gedney's 2011 Springer chapter were verified by metadata/abstract only (paywalled); anchor verbatim psi-confinement claims on Li et al. 2008, Johnson arXiv:2108.05348, and Padilla-Perez et al. 2022, all fetched and quoted.

## 3. Honest "not applicable through XLA" list

1. **Temporal blocking / wavefront-diamond tiling / multi-timestep systolic schemes** (Nguyen et al. SC'10; Holewinski et al. ICS'12; Malas et al. arXiv:1410.3060; AN5D CGO 2020; EBISU ICS 2023; fdtd-z; Lu et al. arXiv:2502.20610) — below XLA's abstraction level: XLA fuses within a step but materializes state to HBM at every scan iteration. Reachable only via custom kernels (Pallas/Triton/CUDA via jax.ffi). Expectation-setting: realistic gains are ~1.3–1.6x for low-order stencils with sources (Bisbas et al. IPDPS 2021, which required dependency surgery for source injection) and 1.49x geomean (up to 2.53x) on modern GPUs (EBISU) — less than the ~4x available from traffic reduction, which is why the patches are sequenced first. PML/boundary auxiliaries add region-dependent dependencies that make time-tiling harder; no dedicated literature exists.
2. **Shared-memory/register 2.5D tiling and register-pressure-aware reordering** (Micikevicius 2009; Rawat et al. PPoPP 2018) — same custom-kernel-only status.
3. **XLA flag tuning** — measured ~0%, and this is a principled null result: every documented flag targets GEMM precision, communication overlap, or launch overhead (JAX GPU performance tips; OpenXLA flags guidance; NVIDIA JAX-Toolbox, which prescribes its flag set for communication-heavy LLM training); none reduce streamed bytes for a bandwidth-saturated single-GPU stencil.
4. **Forcing concatenate fusion in the compiler** — even when Snider & Liang did it, the gain was ~10%; restructuring state is the fix, not fusion heuristics.
5. **Relying on XLA LICM to hoist invariant coefficient/material broadcasts out of the scan body** — while_loop_invariant_code_motion.h hoists constants/reshapes only conditionally and hoist_size_inflation_ratio forbids size-inflating hoists; pre-materialize invariants outside the loop explicitly.
6. **Scan-carry donation specifics** — no authoritative doc beyond the general buffer-donation/aliasing pages; "the carry is aliased in the While body" is folklore — verify in HLO dumps, don't cite.
7. **CUDA MPS for GPU sharing of this workload** — measured −58%; no literature found bearing on MPS for bandwidth-saturated kernels; state as novel operational data, no citation available.
8. **Closing the final gap to hand-tuned CUDA inside XLA** — documented residual gap of ~2.1–2.4x across comparable codes (Shan & Araya-Polo: tuned CUDA 2.1x over optimized OpenACC stencils; JAX-MD: ~2.4x vs LAMMPS/HOOMD; XLB: concedes the gap and added a Warp backend). The defensible goal in JAX is closing the bytes gap (648 → ~100–150 B/cell/step), with Veros/Häfner as precedent that byte-lean JAX stencil codes reach production-competitive throughput.
